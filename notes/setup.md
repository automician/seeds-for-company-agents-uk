# Технічні кроки — для агента, разом із людиною

Читай цей файл, коли людина прийшла з чату (у тебе немає доступу до файлів) або
репозиторій ще не її приватна копія. Людині — прості слова, без жаргону; команди
виконуй сам, де маєш доступ, інакше диктуй по одній і перевіряй результат.

## 1. Хто що робить

Спершу скажи людині, що зробить вона сама: завести обліковий запис у сервісі
зберігання коду, створити приватне сховище, поставити інструмент, дати йому
доступ до теки. Решта — твоє: команди, перевірки, перший запуск; по кроку.

## 2. Приватна копія

- Сховище компанії — ПРИВАТНЕ: GitHub, GitLab або власний сервер. Не форк: форк
  публічного репозиторію на GitHub приватним не буває.
- Копія: `git clone <адреса публічного репозиторію>`, далі
  `git remote set-url origin <адреса приватного сховища>` і
  `git push -u origin HEAD`.
- Публічний репозиторій лишається джерелом оновлень лише для теки `seeds/`:
  `git remote add upstream <адреса публічного репозиторію>`; оновлення —
  `git fetch upstream` і `git checkout upstream/main -- seeds/`.

## 3. Інструмент

- Claude Code, Codex чи подібний — той, що працює з файлами в теці копії.
- Інструмент не читає `AGENTS.md` сам (Claude Code старіший за 2.1.277, з
  вимкненим читанням `AGENTS.md`, або над текою лежить чийсь `CLAUDE.md`) —
  додай у корінь `CLAUDE.md` з одним рядком `@AGENTS.md`.

## 4. Історія змін

- git — обов'язково.
- jj (поверх git, у тій самій теці — `jj git init --colocate`) — рекомендуємо
  розробникові, готовому його поставити: конфлікти — звичайний стан, а не
  зупинка; журнал операцій дає відкат будь-якого кроку. Інакше — лише git.

Далі: скажи людині відкрити інструмент у теці копії й сказати «прочитай
`AGENTS.md` і продовж» — `seeds/first-run.md`, крок 0.
