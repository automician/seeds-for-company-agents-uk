# Зерно: перезапуск — `core/rehatch.sh`

Виростити `core/rehatch.sh` — наглядача, який запускає наступну сесію сам, коли
людина вже кілька разів запускала сесії вручну й довіряє тому, як вони
завершуються. До того наступну сесію запускає людина.

## Що несе артефакт

- **Коли запускати.** Сесія завершилась; лінія не чекає людину (відкладені
  задачі лінію не зупиняють), і `AGENDA.md` каже «продовжити» або триває серія,
  яку увімкнув оператор (`core/run.md`); зупинного файлу (`REHATCH_STOP_FILE`)
  немає; денний ліміт (`REHATCH_MAX_SESSIONS_PER_DAY`) не вичерпано;
  використання підписки (у відсотках від ліміту) чи витрати API нижчі за поріг
  із `company/sessions.md`.
- **Як.** Запуск без людини фразою «прочитай `AGENTS.md` і продовж»: на маршруті
  API серія працює без комп'ютера оператора, а інша версія чи налаштування
  інструмента можуть не підхопити правил, і помітити це нікому. Режим дозволів,
  названий у скрипті явно, затвердила людина; кожен запуск — рядок у журналі
  запусків (`core/rehatch.log`: коли, яка сесія, чим закінчилась).
- **На чому.** Лише на маршруті API або на робочому місці, умови якого
  перевірено для автоматичного доступу, — ніколи на особистій споживчій
  підписці: умови забороняють (`notes/honest.md`).
- **Зупинка.** Будь-яка помилка запуску, два поспіль завершення без контрольної
  точки, стан «лінія чекає людину» — наглядач зупиняється й пише людині у звіт.

## Приймання

- Тестовий запуск: три сесії поспіль запустились самі, кожна лишила контрольну
  точку і звіт; покладений зупинний файл зупинив четверту.
- Журнал запусків є й читається.

## Застереження

- Наглядач не розширює дозволів сесії й не змінює межі з `AGENTS.md`.
- Ліміти запусків — у `.env` і `company/sessions.md`, не в скрипті: людина міняє
  їх без правки коду.
