# Зерно: автозапуск — `core/rehatch.sh`

Виростити `core/rehatch.sh` — наглядача, який запускає наступну сесію сам, коли
людина вже кілька разів запускала сесії вручну й довіряє тому, як вони
завершуються. До того наступну сесію запускає людина.

## Що несе артефакт

- **Коли запускати.** Будь-який запуск — лише коли: рядок «Хто зараз пише» в
  `AGENDA.md` порожній — жодна сесія не працює; лінія не чекає людину
  (відкладені задачі лінію не зупиняють); зупинного файлу (`REHATCH_STOP_FILE`)
  немає; денний ліміт (`REHATCH_MAX_SESSIONS_PER_DAY`) не вичерпано;
  використання підписки (у відсотках від ліміту) чи витрати API нижчі за поріг
  із `company/sessions.md`. Запис, старший за граничний час сесії
  (`core/session.md`, Старт, пункт 3), для наглядача теж не порожній: наглядач
  зупиняється («Зупинка»), а запис знімає сесія оператора. В окремій копії
  репозиторію наглядач спершу забирає зміни з приватного сховища компанії
  (`core/field.md`, «Хто зараз пише»). Продовження — після завершення сесії (не
  запущене через ліміт чи поріг — щойно вони дозволять), коли робота триває:
  рядок роботи в останньому звіті — без «закрито» і його кінець не настав (поза
  маршрутом API — ще й сьогоднішній; `core/run.md`, «Сигнал» і «Автозапуск»).
  Нова серія — коли спрацював тригер, записаний у `company/sessions.md` §
  Автозапуск (розклад, сигнал іншої системи чи дія іншої людини), і жодна робота
  не триває, — і лише там, де це допускає «На чому». Тригер, що спрацював, поки
  нової серії запустити не можна, наглядач записує в журнал запусків як
  відкладений і запускає з ним нову серію, щойно можна: відкладені — по одному,
  у порядку спрацювання; кілька спрацювань одного тригера — один запуск. Запис
  тригера в журналі стає «запущено», лише коли сесія його серії зробила першу
  контрольну точку чи дійшла § Завершення зі своїм звітом; доти тригер лишається
  відкладеним — і тоді, коли сесія відклала його у звіті
  (`сигнал серії відкладено`) чи поступилась. Після власного перезапуску
  наглядач спершу читає відкладені записи журналу. Кінець роботи настав між
  сесіями, а рядок — без «закрито»: на маршруті API наглядач запускає нову серію
  з відкладеним тригером, якщо такий є (її сесія закриє цей рядок), а інакше —
  продовження, щоб сесія закрила роботу й написала її підсумок
  (`core/session.md`, Старт, пункт 5); поза маршрутом API після кінця роботи
  наглядач не запускає нічого — рядок закриває наступна сесія.
- **Як.** Продовження — фразою «прочитай `AGENTS.md` і продовж роботу
  (наглядач)»; нова серія — «прочитай `AGENTS.md` і почни серію:
  `<сигнал серії>` (наглядач)», із фразою, записаною для тригера в
  `company/sessions.md` § Автозапуск. З «(наглядач)» сесія знає, хто її запустив
  (`core/session.md`, Старт, пункт 5). На маршруті API серія працює без
  комп'ютера оператора — у своїй копії репозиторію, що обмінюється змінами з
  іншими через приватне сховище компанії (`core/field.md`, «Хто зараз пише»);
  інша версія чи налаштування інструмента там можуть не підхопити правил, і
  помітити це нікому. Режим дозволів, названий у скрипті явно, затвердила
  людина; кожен запуск і кожне спрацювання тригера — рядок у журналі запусків
  (`core/rehatch.log`: коли, яка сесія чи який тригер, стан — запущено чи
  відкладено — і чим закінчилась запущена сесія: з контрольною точкою, без неї,
  «лінія чекає людину», «завершилась на старті» чи «поступилась»; про
  «поступилась» сесія каже останнім повідомленням — це не помилка запуску).
- **На чому.** Три підстави ввімкнути наглядача: (1) маршрут API — будь-який
  запуск, і лише тут — запуск за розкладом, за сигналом іншої системи чи за дією
  іншої людини (задача, яку хтось поставив у трекері, сповіщення з нього); (2)
  робоче місце, чиї умови, за записаною перевіркою, прямо дозволяють
  автоматичний доступ (документація про запуск зі скриптів на підписці таким
  дозволом не названа — `notes/honest.md`, «Підписки», «Відкрите»); (3) робоче
  місце без такого дозволу (зокрема особиста підписка оператора чи оплачена
  компанією) — лише зі слова керівника компанії: це сіра зона умов, рішення
  компанії на її власний ризик, а не дозвіл постачальника. Поза маршрутом API
  (підстави 2 і 3) наглядач лише продовжує роботу, яку того дня вручну почав
  оператор (серію чи роботу над чергою), до її кінця — правило міста
  (`notes/honest.md`, «Підписки»). Що з цього є — `company/sessions.md` §
  Автозапуск: робоче місце, що показала перевірка умов і коли, слово керівника
  (роль, дата). Маршруту API й записаного прямого дозволу немає, а в §
  Автозапуск стоїть «не питали», — сесія цього зерна ще до скрипта пише в «Чекає
  людину» питання оператору (спитати керівника) і свій нахил; слово керівника
  вписує в § Автозапуск (роль, дата) та сесія, якій оператор його передав. Немає
  жодної з трьох підстав — скрипт можна виростити, але не вмикати (рядок у
  «Чекає людину» — «Приймання»).
- **Зупинка.** Будь-яка помилка запуску, запис у «Хто зараз пише», старший за
  граничний час сесії («Коли запускати»), два поспіль завершення без контрольної
  точки (не рахуються сесії, що поступились чи завершились на старті —
  `core/session.md`, Старт, пункт 5), стан «лінія чекає людину» — наглядач
  зупиняється й пише людині у звіт.

## Приймання

- Тестовий запуск: три сесії поспіль запустились самі (поза маршрутом API — у
  роботі, яку того дня вручну почав оператор: серія чи «продовж»), кожна лишила
  контрольну точку і звіт; покладений зупинний файл зупинив четверту. Немає
  жодної з трьох підстав «На чому» — тестового запуску не роби: зерно виросло,
  але не прийняте; у «Чекає людину» — рядок «прийняти `rehatch` — тест, коли
  з'явиться підстава з «На чому»»; лінія йде далі.
- Журнал запусків є й читається.

## Застереження

- Наглядач не розширює дозволів сесії й не змінює межі з `AGENTS.md`.
- Ліміти запусків — у `.env` і `company/sessions.md`, не в скрипті: людина міняє
  їх без правки коду.
